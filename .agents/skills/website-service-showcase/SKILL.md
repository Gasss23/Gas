# Website service showcase

Use this workflow for a business or professional site whose main goal is to start conversations with prospective customers.
When available, consult `marketing:content-creation` for landing-page structure and CTA wording; this skill captures the compact site-review and preview workflow used by the GAS agent.

## Workflow

1. Open the supplied URL and inspect the current page, its content, calls to action, and any visible forms. Check the workspace for the actual source project. Distinguish a hosted page from an editable local project.
2. Identify the audience, services, desired action, brand elements worth keeping, and missing facts. If unclear, draft a useful preview and ask only for details that block a working contact path or accurate claims.
3. Keep the page to the sections the user needs: a short hero, concise service cards or scroll chapters, and a repeated primary CTA. Add FAQ or social proof only when requested. Keep public copy at the requested detail level; direct specific questions, terms, and percentages to the conversation.
4. Use only supplied or verified facts. Never invent results, customer endorsements, guarantees, credentials, or performance data. Clearly label fictional copy as a mockup; replace it with authentic, authorized testimonials before publication. For financial offers, describe guarantees only as supported by their actual documents and avoid promises of return.
5. Design mobile-first, keep navigation and copy simple, and remove decorative trading screens or charts unless requested. If given a visual reference, inspect its scroll response and borrow the pacing, not its brand or assets. For 3D, choose one object that fits the business and tie it to the main content; prefer real WebGL geometry with visible depth, lighting, and perspective over rotating a still render. Interpolate movement directly at scroll-frame cadence, avoid long per-scroll transitions and section background bands, and honor reduced-motion preferences.
6. Make every primary CTA open the user's stated contact channel. For WhatsApp, use the supplied number in an international `wa.me` link and a short prefilled message; do not send a message on the user's behalf.
7. If source access exists, edit the site and preview the result; publish only when the user explicitly authorizes publication. If source is unavailable, save a standalone preview in the task's writable artifact folder and state that the live site is unchanged. Never imply a preview has been deployed.
8. Report the preview path, live/deployed status, verification performed, and any missing access, contact details, or proof needed before publication. Get the user's review before publishing when they asked to approve the design first.

## Copy pattern

- Hero: one clear value statement, a short orientation, one primary contact action.
- Services: name each offer and say what the prospect can ask about; omit unprovided terms and specifics.
- Trust: prefer process clarity and authentic evidence. Use transparent examples instead of fabricated social proof.
- Close: repeat the contact action and say what the first conversation will cover.
